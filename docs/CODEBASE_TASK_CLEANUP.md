## Identity and access contracts

### Campaign grouping

`assignments.campaign_id` accepts a valid UUID from the registering/importing authority. It groups assignments but is not an authorization claim. Assignment membership and supervisor authorization remain the access boundaries. Some historical local imports use the assignment UUID as the campaign UUID; preserve those identifiers.

Unknown campaign UUIDs are valid under this external contract. A future local campaign registry must inventory and backfill all historical values before adding an existence constraint. Do not create empty invented campaigns, change assignment IDs, or drop assignments to satisfy the historical initial-schema TODO. Revisit when campaign lifecycle or cross-assignment reporting requires a managed registry.

### Enrollment and revocation

Gateway supervisor authorization controls membership administration. An assignment membership role of `owner` does not make its holder a gateway supervisor. Gateway activation must retain its explicit policy for disabling legacy name-based self-claim; legacy configurations need their own reviewed roster and access contract.

Removal blocks subsequent authorized online requests according to the supported endpoint contract. It cannot erase a downloaded phone copy. Public photo links are intentionally independent of membership revocation unless the product adopts a new read-access contract with GIS compatibility.

### Field configuration compatibility

CBMS ID has no new format restriction. An explicit `None` facilities answer counts as answered. Both fields remain optional when their new requirement keys are absent; explicit `required` applies to applicable, visible questions. Existing required-field defaults and mandatory photo evidence remain unchanged. Form-definition visibility/editability continues to apply.

## Safe retention procedure

Inventory only configured gateway roots and stable metadata. Keep all advertised versions, registered upload batches, incomplete/resumable work, archive history, and unknown/unattributable folders protected. Compare references again at report completion and label candidates as inconclusive if state changes. An absent database reference alone is not permission to delete: a folder may belong to an in-flight transaction or historical evidence.

The initial delivery has no automatic deletion mode. Review candidates by exact folder ID, reason, creation time when known, reference snapshot, and source root. Define retention age, concurrent-operation grace period, recovery method, responsible reviewer, and authorization before developing or invoking apply mode. Do not apply Research workspace retention rules to this unrelated project.
